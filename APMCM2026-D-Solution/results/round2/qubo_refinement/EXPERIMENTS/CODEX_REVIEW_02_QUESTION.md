# V4 one-hot 稳定性数学核验

只核验本目录文件，不访问仓库其他内容，不修改文件。

## 假设与证据

H1：对 V≥0 的 one-hot 表达，`M>max V` 保证所有合法解严格优于所有非法解。把 M 从默认 M0 降到接近阈值，可降低 `max|I|`、减小量化步长、提高 resolution；但“降低 M 会单调提高目标保真”不成立。

证据：
- `lowm_coeff_delta.json`：B-Q2-NO2 topk=8，M0=42.170953，lowM=14.264750（mfactor=0.338260）；目标块 Q 不变；Q/I/adj 分别有 72/144/252 个系数改变；max|I| 72.23→30.37；量化步长 0.5687→0.2391；平均舍入误差 0.3287→0.1813；resolution 2.99→7.10（8bit 后 3→7）。
- `onehot_mfactor_scan_results.json`：同输入，M/Vmax 从 1.02 到 3.50 扫描。Q2 只有在 1.05、1.10 时“保留 1.0 且非原始最优 0”；1.02 有额外非原始最优 1，1.20 也额外 1，≥1.40 丢失原始最优。Q3 O3 没有集合相等，最高保留 0.667；Q3 FO2 有保留 1.0 但非原始最优 3/6，集合不相等。
- `RESULTS.md`：实际真机 B_Q2_k8_lowM 返回 La-Zr（H=−1716，V=0），原始命中 1/1，合法 2/10；仅单任务。

## 需要核验

1. one-hot 构造、M 缩放、合法成本等于 V、全空间枚举与量化路径是否正确；`lowm_coeff_delta.py` 的系数差异口径是否合理。
2. `M>max V` 的严格条件（等号、并列）是否表述正确；扫描中 exact_valid 全 true 是否符合理论。
3. 为什么 Q2 的集合相等窗口只有 1.05–1.10，而 1.02、1.20 出现额外非原始最优、≥1.40 丢失？请从逐系数舍入/能量间隙角度给出数学解释或反例框架。
4. 是否存在可证明的“集合保持窗口”条件（例如用合法-次优间隙 vs 2ε、或存储项 C(g,t) 的带符号舍入误差），以及为什么不能只靠 resolution 或 M 单调性判断。

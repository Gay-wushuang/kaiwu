# 三人团队分工建议

> 前提：本文件只给分工与流程建议，不包含 D 题建模方案或结论。正式赛题工作由队员完成。

---

## 1. 角色划分

| 角色 | 代号 | 核心职责 | 需要补齐的知识 |
|---|---|---|---|
| 建模负责人 | A | 把 D 题翻译成 QUBO：决策变量、目标函数、约束、惩罚系数、比特预算 | QUBO 写法、惩罚项、松弛变量 |
| 实验负责人 | B | 环境、SDK 调用、精度适配、真机提交与结果记录、复现脚本 | Kaiwu SDK API、8bit 精度、Tabu/SA |
| 论文负责人 | C | 问题重述、假设、符号、图表、摘要、排版、合规披露 | APMCM 格式、引用规范 |

补充约定：

- **license 与真机账号由 A（队长）统一持有**，B 只在本机跑，不共享凭据。
- 真机任务提交必须 A 确认，B 执行，C 记录（任务号、时间、消耗、结果）。
- 任何人不允许在公共聊天/文档/Git 中粘贴 `user_id`、`sdk_code`、密码、验证码。

---

## 2. 工作流与接口

```text
A 产出：模型文件（变量定义 + 目标 + 约束 + 比特预算表）
   ↓ 交接物：docs/model_spec.md（队伍私有，不在本仓库）
B 产出：可运行脚本 + 结果 JSON + 日志
   ↓ 交接物：experiments/results/*.json、logs/*.log
C 产出：图表 + 论文段落 + 复现说明
   ↓ 交接物：reports/、论文 PDF
```

三条硬规则：

1. **先本地、后真机**：所有模型先在本地用 Tabu / BruteForce 验证约束和量级，真机只做最终确认。
2. **每次实验必须留日志**：命令、时间、矩阵规模、结果、异常，全部落 `logs/`。
3. **结果必须可复现**：随机种子固定，脚本参数写死或存 JSON。

---

## 4. 分工禁忌

1. **不要让一个人同时做建模和真机**：真机排队会打断建模思路。
2. **不要让论文负责人最后才介入**：摘要和符号表需要从第一天开始写。
3. **不要三人同时改同一份脚本**：脚本按 `examples/` 分文件，改动前先在群里说。
4. **不要用 AI 生成正式论文段落直接提交**：合规风险由队伍承担，AI 产出必须人工重写与核对。

---

## 5. 每日站会（15 分钟）

固定回答四个问题：

1. 昨天完成了什么（可验证的产出）？
2. 今天要完成什么（对应哪个检查点）？
3. 当前阻塞是什么（账号/配额/数据/API）？
4. 是否需要触发止损点？

站会结论记录到 `logs/daily_standup.md`（由 C 维护）。

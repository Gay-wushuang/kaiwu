### 2.3 真机调用的技术约束（文档 + 实测）

| 约束 | 内容 | 来源 |
|---|---|---|
| 输入形式 | 真机求解的是 **Ising 矩阵**（QUBO 需先转换） | 官方"参数精度"页 |
| 系数精度 | 8bit 有符号整数 `[-128, 127]`，整体等比缩放不改变可行性 | 官方"参数精度"页 |
| 线性项 | Ising 矩阵对角线必须为 0；线性项通过 **1 个辅助自旋**转为二次项 | 官方文档 + 实测 3→4 |
| 计算模式 | `TaskMode.OPTIMIZATION`（默认）/ `TaskMode.SAMPLING`（需 `sample_number`，10–2000） | 官方模块手册 |
| 任务标识 | 由 `task_name` 与 Ising 矩阵共同决定；换名可对同一矩阵重复建任务 | 官方模块手册 |
| 本地缓存 | 需先设置 `kw.common.CheckpointManager.save_dir`，否则中间文件无处落盘 | 官方模块手册 |
| 轮询间隔 | `interval` 单位秒，默认 6，最小 5；`wait=False` 时未完成任务可能返回 `(None, None)` | 官方模块手册 + changelog |
| 授权 | 首次使用 `CIMOptimizer` 需 `user_id` + `sdk_code` 生成 license | 官方安装说明 + 实测（SA 同样被拦截） |

### 2.4 结果获取方式（文档描述，未实测）

两条路径，均需登录：

1. **网页端**：控制台 → 新建任务 → 上传矩阵 → 校验 → 排队 → 完成 → 结果详情（QUBO 解向量、QUBO value 演化曲线、任务执行时间）。
2. **SDK 端**：`CIMOptimizer(task_name=..., task_mode=...)`，`solve` 返回解数组；结果可缓存复用。

网页端是否支持导出 CSV/报告、SDK 结果是否能直接落盘为报告，属于**未实测**项。

## 4. 人工操作清单（按顺序执行）

> 以下步骤需要队员本人完成。**不要把密码、验证码、Token、sdk_code 发到聊天、文档或 Git 仓库。**

### 步骤 A：登录并记录账号信息（约 5 分钟）

1. 打开 <https://platform.qboson.com/>，用队伍统一账号登录。
2. 进入个人中心 / SDK 下载页，找到：
   - `user_id`
   - `sdk_code`（SDK 授权码）
3. 只记录"是否已获取"（是/否），**不要记录具体值**。
4. 在本机执行（凭据只留在本机）：

```powershell
cd APMCM2026-D-Feasibility
environment\.venv\Scripts\python.exe -c "import kaiwu as kw; kw.license.init(input('user_id: '), input('sdk_code: ')); print('license init done')"
```

5. 验证：

```powershell
environment\.venv\Scripts\python.exe environment\verify_env.py
```

验收标准：`SimulatedAnnealingOptimizer: PASS`（不再是 `BLOCKED_LICENSE`）。

### 步骤 B：竞赛页与算力（约 10 分钟）

1. 打开竞赛页：
   <https://kaiwu.qboson.com/plugin.php?id=crowdsourcing&modac=contractorCompetitionDetail&modacPage=competitionList&type=competition&taskId=80>
2. 确认并记录（只需回答是/否/数值）：
   - 是否需要额外报名？报名入口在哪？
   - 是否有高校学生认证？认证材料与审核时长？
   - 竞赛专属算力如何领取？额度多少？有效期到哪天？
   - 本账号可用真机型号与最大比特数？
3. 把答案填回本文件第 3 节对应行，状态从 BLOCKED 改为 PASS。

### 步骤 C：设备与配额确认（约 5 分钟）

1. 在平台控制台查看"我的配额/我的算力"。
2. 记录：可用机型、剩余次数、单次最大比特数、到期时间。
3. 若单次最大比特数 < D 题建模所需比特数，立即在 `FEASIBILITY_REPORT.md` 中把"硬件容量适配"改为 FAIL，并触发选题复核。

### 步骤 D：真机提交授权（必须人工确认后才执行）

提交真机任务前，队长需要在群里明确回复：

- 任务数量（建议首次只提交 1 个）
- 预计消耗额度
- 任务矩阵规模（比特数）
- 是否已确认结果可复现

得到确认后，才执行 `examples/` 下的真机脚本（Phase 5 尚未编写，等授权后再写，避免误提交）。

## 5. 风险提示

1. **账号是单点瓶颈**：license 与 user_id 绑定，三人不能各自独立跑真机。建议队长账号统一管理，队员只跑本地实验。
2. **配额可能远小于设备上限**：FAQ 已出现"100 配额"场景。若 D 题需要数百比特，必须先确认配额，否则建模完成也提交不了。
3. **排队时间不可控**：比赛只有约 3.5 天，若排队数小时，实验迭代次数会被严重压缩。
4. **不要为了"试一下"提交真机任务**：每次提交都消耗额度，且可能影响队伍配额记录。

# 通用教学案例测试报告（Phase 2 + Phase 3）

- 测试时间：2026-11-26
- 测试对象：Kaiwu SDK 1.4.4（企业版）+ `kaiwu-community` 1.0.8
- 测试环境：Windows 10 22H2 / Python 3.12.6 / 独立 venv
- 测试性质：**仅通用教学问题**（整数划分、背包、TSP、最大独立集），与 D 题无关
- 结论：**QUBO→Ising→求解→解码→校验链路 PASS；本地经典求解器可用，但官方 SA 优化器被 license 阻塞。**

---

## 1. 测试方法

每个案例都走同一条链路，并做三重校验：

```text
数学问题
  → 用 kw.core 构造 QUBO 表达式（目标 + 硬约束惩罚）
  → QuboModel.get_matrix() 得到 QUBO 矩阵（含惩罚项）
  → qubo_model_to_ising_model() 得到 Ising 矩阵（自动 +1 辅助自旋）
  → BruteForceOptimizer().solve(ising_matrix)
  → get_sol_dict(sol, ising_model.get_variables()) 解码
  → get_val(objective, sol_dict) 还原目标值
  → verify_constraint(sol_dict) 检查硬约束
```

三重校验：

1. **与独立全枚举对比**：用 numpy 枚举 `2^n` 个 0/1 组合，直接算 `xᵀQx + offset`，取最小。
2. **与问题已知答案对比**：如整数划分最优差为 0、4 城市 TSP 最优 11。
3. **硬约束检查**：`QuboModel.verify_constraint` 返回的违反数必须为 0。

### 2.2 各案例的数学含义（给初学者）

#### 案例 1：整数划分

- 输入：`a = [8,7,6,5,4]`，总和 `S = 30`
- 决策变量：`x_i = 1` 表示第 i 个数放入 A 组，否则 B 组
- 两组之差：`D = 2·Σ a_i x_i − S`
- 目标：`min D²`
- 输出：`x = [0,0,1,1,1]`，即 A = {6,5,4} = 15，B = {8,7} = 15，差值为 0
- 说明：这是最干净的 QUBO 入门例子，没有硬约束，`D²` 展开后自然得到二次项。

#### 案例 2：0/1 背包

- 输入：重量 `[3,4,5,2]`，价值 `[4,5,6,3]`，容量 `10`
- 决策变量：`x_i = 1` 表示选第 i 件
- 目标：`max Σ v_i x_i`，QUBO 中写成 `min −Σ v_i x_i`
- 约束：`Σ w_i x_i ≤ 10`，用 `add_constraint(..., penalty=10)` 自动引入 4 个松弛变量
- 输出：选物品 0、2、3，重量 `3+5+2 = 10`，价值 `4+6+3 = 13`
- 说明：**不等式约束会自动增加变量**，这是估算比特数时最容易漏掉的一项。

#### 案例 3：4 城市 TSP

- 输入：距离矩阵 `w`，`x[u][j] = 1` 表示第 j 个位置访问城市 u
- 目标：路径总长度最小
- 约束：每个城市恰好出现一次、每个位置恰好一个城市（`x.sum(axis=0) == 1`、`x.sum(axis=1) == 1`）
- 输出：`0 → 2 → 1 → 3 → 0`，总长 `3+5+1+2 = 11`
- 说明：16 个变量 + 8 个等式约束，是四个案例中唯一需要 0.5 秒暴力求解的。

#### 案例 4：最大独立集

- 输入：5 个节点，边 `(0,1),(1,2),(2,3),(3,4),(4,0),(0,2)`
- 决策变量：`s_i = 1` 表示选中节点 i
- 目标：`max Σ s_i`，QUBO 中写成 `min −Σ s_i`
- 约束：每条边不能同时选中，`add_constraint(s_u + s_v <= 1, penalty=5)`
- 输出：选中 `{2,4}`，大小 2
- 说明：这是最接近"带约束的组合优化"的形态，也是 D 题类问题（从候选中选子集并满足互斥）的最小原型。

## 3. Phase 3 结果

脚本：[classical_solver_check.py](../examples/classical_solver_check.py)
原始结果：[phase3_classical.json](../experiments/results/phase3_classical.json)

### 3.1 求解器可用性（子进程 + stdin 关闭，实测）

| 求解器 | 类型 | 是否需要 license | 实测状态 |
|---|---|---|---|
| `kw.classical.BruteForceOptimizer` | 精确枚举 | **否** | PASS |
| `kw.classical.TabuSearchOptimizer` | 禁忌搜索 | **否** | PASS |
| `kw.sampler.SimulatedAnnealingSampler` | SA 采样器 | **否** | PASS |
| `kw.classical.SimulatedAnnealingOptimizer` | SA 优化器 | **是** | **BLOCKED_LICENSE** |
| `kw.cim.CIMOptimizer` | 真机 | **是**（且消耗算力） | 未提交，未消耗 |

> 这条结论很重要：**没有 license 也能完成建模、转换、基线求解和精度适配**，只是不能用官方 SA 优化器和真机。

### 3.2 BruteForce 规模-耗时（随机对称 Ising，固定种子 20261126）

| 比特数 n | 矩阵 | 返回解数 | 耗时(s) | SDK 最优能量 | 独立枚举最优能量 | 一致 |
|---|---|---|---|---|---|---|
| 8 | 8×8 | 4 | 0.0011 | -126.0 | -126.0 | 是 |
| 12 | 12×12 | 2 | 0.0166 | -302.0 | -302.0 | 是 |
| 16 | 16×16 | 2 | 0.2550 | -542.0 | -542.0 | 是 |
| 18 | 18×18 | 2 | 1.1291 | -570.0 | -570.0 | 是 |
| 20 | 20×20 | 2 | 13.7868 | -794.0 | -794.0 | 是 |

结论：

- BruteForce **结果正确**，但复杂度是 `O(2ⁿ)`；20 bit 已需 14 秒，24 bit 约 4 分钟，**无法用于正式规模问题**。
- 它的价值是"小规模真值基准"，用来验证建模和精度适配是否正确。

### 3.3 8bit 精度适配工具链（4 城市 TSP 的 Ising 矩阵，17×17）

| 指标 | 实测值 |
|---|---|
| Ising 矩阵尺寸 | 17×17（16 变量 + 1 辅助自旋） |
| 最小非零系数 | 0.125 |
| 最大系数 | 23.5 |
| 动态范围指标 | 7.5546 |
| `calculate_ising_matrix_bit_width(mat, 8)` | `precision = inf`（即该矩阵**不能**在 8bit 内精确表示） |
| 原始最优能量 | -351.0 |

三种降精度方案的结果：

| 方法 | 调用 | 矩阵变化 | 是否保持最优解 | 耗时(s) |
|---|---|---|---|---|
| 直接截断 | `adjust_ising_matrix_precision(mat, bit_width=8)` | 17×17，元素变为 `[-127,127]` 整数 | **是**（该算例） | 0.0001 |
| 动态范围压缩 | `perform_precision_adaption_mutate(mat)` | 17×17，max\|J\| 从 23.5 降到 47（缩放后） | **是** | 0.1812 |
| 变量拆分 | `perform_precision_adaption_split(mat, param_bit=8, min_increment=0.125)` | 17×17 → **19×19**（+2 bit） | **是**（还原后能量 -351.0） | 0.0006 |

重要提醒：

1. "保持最优解"只在**这一个小算例**上验证，不能外推为通用保证。官方文档明确说：存在极端值时直接截断会严重失真。
2. 变量拆分会让比特数增长，**直接吃掉真机配额**。D 题若规模大，这一项必须提前算清楚。
3. 判断"能否上真机"的正确顺序是：先算 Ising 矩阵位宽，再选降精度方法，最后核对拆后比特数 ≤ 账户配额。

### 3.4 无 license 随机求解器稳定性（12bit 随机 Ising，真值 -246.0）

| 求解器 | 运行次数 | 命中最优次数 | 命中率 | 平均间隙 | 单次耗时 |
|---|---|---|---|---|---|
| TabuSearch（1000 次迭代） | 5 | 5 | 1.00 | 0.00 | < 0.01 s |
| SA Sampler（100 条链） | 3 | 3 | 1.00 | 0.00 | 约 5 s（含日志开销） |

结论：在小规模随机 Ising 上，两个免 license 求解器都能稳定命中全局最优；规模上去后是否仍稳定，需要按 D 题实际规模再测（尚未验证）。

## 4. 调试过程中发现并修正的问题（可作为团队培训材料）

| 问题 | 现象 | 原因 | 修正 |
|---|---|---|---|
| 能量符号搞反 | SDK 最优值与全枚举最小值差一个负号 | SDK 约定 `H = −sᵀJs`，求解器最小化 H，等价于**最大化** `sᵀJs` | 校验代码统一用 `−sᵀJs` |
| 漏加 offset | 整数划分 SDK 得 0，全枚举得 -900 | QUBO 目标含常数项（如 `S² = 900`），`get_matrix()` 只含系数不含 offset | 用 `model.make().offset` 加上 |
| 变量顺序错位 | 背包/独立集解码结果看起来"多出几个变量" | 不等式约束自动插入松弛变量，且排在用户变量之前 | 一律按变量名解码，不按位置 |
| 变量名写错 | `KeyError: 't[0,0]'` | `kw.core.ndarray` 的命名是 `t[0][0]` | 按实际命名读取 |
| 位宽函数用错 | `int(dict)` 报 TypeError | `calculate_ising_matrix_bit_width` 返回 `{precision, multiplier}` | 取字典字段 |
| 版本判断错误 | `kw.__version__` 显示 1.0.8 | 该属性来自 `kaiwu-community` | 用 `importlib.metadata.version("kaiwu")` |
